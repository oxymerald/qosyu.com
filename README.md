# QOSYU — цифровая первая миля переработки

## Карта и планирование — этапы 7 октября 2026

План и состояние работ: [ROADMAP.md](ROADMAP.md). Кабинет использует светлые
панели и карту, на телефоне панель заявок можно свернуть. В заявке сохраняются
необязательные адрес (300 символов) и инструкция к подъезду (500 символов).
Старые записи остаются доступны: при запуске применяется повторяемое добавление
двух nullable-колонок. Перед обновлением существующей установки сделайте копию базы.

Для 2–8 остановок порядок рассчитывается по направленной матрице времени движения
2ГИС. Затем Routing API строит геометрию этого объезда. Матрица кэшируется на 5 минут;
по умолчанию разрешено 24 новых расчёта за окно 24 часа на весь сервер, каждый не
более 81 пары точек. Квота поставщика списывается за пары, а не за HTTP-запросы.
`DGIS_MATRIX_ENABLED=false` отключает матрицу; `DGIS_MATRIX_DAILY_REQUESTS` задаёт
локальный бюджет. С Redis счётчик общий; при недоступности Redis он локален процессу.
Это ограничитель запросов, не гарантия суммы счёта провайдера.

Если матрица недоступна, порядок определяется расстояниями по координатам; интерфейс
явно сообщает об этом. При недоступности дорожного сервиса применяется OSRM, затем
пунктирная схема. Больше 8 остановок обслуживает резервный расчёт без потери точек.
Маршрут возвращается к старту. Вместимость, совместимость сырья и часы приёма пока
не учитываются. Время погрузки — предположение 6 минут на остановку.

Отдельный следующий этап — MapGL: текущая карта использует Raster Tiles и Leaflet.
Доступ к Map Tiles подтверждён владельцем, но векторный движок ещё не подключён.
Для него следует выпустить отдельный браузерный ключ только с картографическими
сервисами и ограничениями для адресов сайта. Общий серверный ключ не публикуется.
Документация: [MapGL](https://docs.2gis.com/mapgl/start/first-steps),
[Distance Matrix](https://docs.2gis.com/api/navigation/distance-matrix/start).

### Резервная копия данных

Запустите `backup-database.ps1` из папки проекта. Архив PostgreSQL появится в
`backups/` с датой и временем; скрипт проверяет читаемость оглавления архива.
Храните копию этого каталога отдельно от ноутбука: GitHub его не содержит.
Дамп содержит данные пользователей; не публикуйте его. `.env` хранится отдельно.
При восстановлении сначала разверните отдельную базу и проверьте данные; не
восстанавливайте поверх рабочей базы без отдельной свежей копии.

В режиме `ENVIRONMENT=production` вход ограничен 20 попытками за 5 минут с IP.
Для локальной демонстрации вход остаётся без ограничения, как было настроено ранее.
Просмотр маршрутов ограничен 30 запросами в минуту и 60 в час с IP.

## Локальная демонстрация — обновление 7 октября 2026

### Подключение 2ГИС и Google AI Studio / Gemini

Откройте `configure-apis.cmd` двойным щелчком и вставьте ключи в скрытые поля окна.
Пустое поле сохраняет ранее введённое значение. Скрипт сохраняет ключи только
в локальном `.env` (исключён из Git) и перезапускает сервер.
Ключи не передаются в браузер и не выводятся в консоль.
Автоматический платный запрос при настройке не отправляется. Затем обновите
страницу и откройте вкладку помощника. Наличие ключа в `/ai/status` означает
настроенное подключение; действительность ключа и квота проверяются первым вопросом.

**Когда ключ истёк или заменён:** снова откройте `configure-apis.cmd`, вставьте новый
ключ соответствующего сервиса и нажмите **Save and connect**. Второе поле можно
оставить пустым — его сохранённое значение не изменится. Скрипт перезапустит сервер;
после этого обновите страницу. Править код или пересобирать проект для замены ключа не нужно.
Новый ключ 2ГИС должен иметь доступ к тем же сервисам, а Gemini — к выбранной модели.
Если исчерпана квота всего аккаунта или проекта провайдера, простая замена ключа
того же проекта не восстанавливает квоту.

GitHub хранит код, зависимости, Docker-конфигурацию и тесты. Локальный `.env`,
пользователи и заявки PostgreSQL туда не входят. На новом компьютере выполните
раздел «Запуск»: создайте `.env` из `.env.example`, задайте отдельные
`POSTGRES_PASSWORD` и `SECRET_KEY`, запустите Docker и введите API-ключи.
Для переноса существующих пользователей и заявок нужна отдельная копия базы данных.

Для ключа 2ГИС нужны **Raster Tiles API**, **Geocoder API** и **Routing API**.
Карта в этом демо — 2D через Leaflet и растровые тайлы 2ГИС; MapGL и 3D не реализованы.
Поиск адреса запускается кнопкой; выбранный результат задаёт точку вывоза или базу.
Порядок остановок для 2ГИС выбирает QOSYU (nearest-neighbor + 2-opt), затем Routing API
рассчитывает проезд по дорогам. TSP API не используется; оптимальность не гарантируется.
Точки вывоза передаются как обязательные промежуточные точки (`pref`), а база —
как начало и конец (`stop`). Если остановок больше восьми, используется резервный
OSRM без удаления остановок. Концы дорожной линии могут быть смещены к въезду
на дорогу; смещение базы более чем на 500 м отклоняется.
Повторный одинаковый маршрут хранится в памяти сервера 5 минут. Фоновая подготовка
зон не обращается к 2ГИС. `/maps/status` сообщает наличие настройки, а не проверку ключа.
Документация: [тайлы](https://docs.2gis.com/en/maps/others/rastertiles/overview),
[геокодер](https://docs.2gis.com/api/search/geocoder/overview),
[маршруты](https://docs.2gis.com/en/api/navigation/routing/start).

По умолчанию: `AI_PROVIDER=gemini`, `GEMINI_MODEL=gemini-3.5-flash-lite`.
Модель можно поменять в `.env`, затем выполнить `docker compose up -d backend`.
Примеры: «Покажи мои заявки на картон», «Покажи открытые зоны»,
«Построй маршрут зоны № 5». Номер зоны берите из своего кабинета.
Кнопки в ответе показывают выбранные объекты на карте; доступ проверяется повторно
при нажатии. Назначение и завершение выполняются обычными кнопками кабинета.
Ассистент не обучается на изображении карты: сервер предоставляет ему разрешённые
данные и рассчитывает маршрут через существующую службу.

Один вопрос ограничен 3 обращениями к модели (до 1536 выходных токенов каждое),
5 вызовами внутренних инструментов и 65 секундами. Лимит вопросов — 30 в час
с одного IP. Это ограничения расхода, а не гарантия нулевой стоимости: квота и
тарификация зависят от проекта Google. Просмотр статистики не вызывает Gemini автоматически.
История вопроса и минимальные необходимые сведения о заявках могут передаваться
Google; имена компаний, пароли и ключи инструменты карты не передают.

Документация: [ключи](https://ai.google.dev/gemini-api/docs/api-key),
[модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite),
[вызовы функций](https://ai.google.dev/api/generate-content).

### Запуск и сценарий демонстрации

Запустите Docker Desktop, затем `powershell -ExecutionPolicy Bypass -File ./start-qosyu.ps1`.
После сообщения о готовности откройте указанный локальный адрес (обычно http://localhost:8080).
Фронтенд уже отдаёт сервер: отдельный запуск через VS Code не нужен.

В кабинете бизнеса нажмите на карте в месте вывоза, при необходимости перетащите
метку, укажите материал и массу. В кабинете переработчика сформируйте зоны,
посмотрите маршрут, затем возьмите зону и завершите вывоз. Зелёным обозначены
зоны переработчика; бордовым — открытые. Начальную базу можно выбрать нажатием на карту.

При подключённом ключе карта, поиск адресов и проезд по дорогам используют 2ГИС.
При недоступности 2ГИС карта переключается на OpenStreetMap, дорожный расчёт — на OSRM,
с предупреждением. Без ключа сразу используются OpenStreetMap и OSRM. Для сервисов нужен интернет;
публичные сервисы не гарантируют доступность. Соблюдайте [условия OSM](https://operations.osmfoundation.org/policies/tiles/):
атрибуция остаётся видимой, массовая загрузка и подготовка офлайн-копий не поддерживаются.
Если дорожный сервис не отвечает или возвращает неполный маршрут, показывается
пунктирная схема всех остановок с предупреждением. Это не дорожная навигация.
Время включает условные 6 минут погрузки на точку. OSRM не учитывает пробки;
для 2ГИС запрашивается оценка дорожной ситуации сервиса.
DBSCAN использует расстояние на сфере, порог соседства 2 км. Цепочка соседних точек
может образовать более широкую зону; радиус охватывает фактические точки.
Вместимость автомобиля, совместимость материалов и временные окна пока не учитываются.

Проверка географии без внешних запросов: `PYTHONPATH=app python -m unittest discover -s tests -p test_geo.py -v`.
Тест `test_workflow.py` изменяет данные и запускается только в отдельной тестовой базе
при `QOSYU_ISOLATED_TEST=1`; он проверяет также одновременное назначение зон.
Полная изолированная проверка без платных API-вызовов:

```bash
docker compose -p qosyu-tests -f compose.test.yml up -d --build --wait
docker compose -p qosyu-tests -f compose.test.yml exec -T backend python -m unittest discover -s /tests -v
docker compose -p qosyu-tests -f compose.test.yml down
```

Тестовые данные сохраняются в отдельном томе `qosyu-tests_testdata`.
ИИ остаётся отдельной интеграцией: отсутствие ключа не мешает заявкам и маршрутам.
Показатели CO₂ — расчётные эквиваленты, а не подтверждённая экономия выбросов.

**QOSYU** — цифровая платформа первой мили экологической логистики.
Каждый день сотни кафе, магазинов и офисов выбрасывают по 10–20 кг картона и пластика —
для переработчиков такие объёмы нерентабельны. QOSYU объединяет разрозненные заявки малого
бизнеса в экономически выгодные маршруты: AI-кластеризация (DBSCAN), геооптимизация,
прозрачная ESG-отчётность.

```
Бизнес (кафе, магазины, офисы) → QOSYU (First Mile: объединяет заявки в маршрут) → Переработчик
```

## Возможности

- **Заявки на вывоз вторсырья** — сайт и Telegram-бот, заявка за 20 секунд
- **AI-кластеризация** — DBSCAN группирует соседние заявки в зоны сбора
- **Маршруты** — 2ГИС с локальным выбором порядка остановок или резервный OSRM;
  если дорожные сервисы недоступны, отображается пунктирная схема прямых отрезков
- **AI-ассистент** — Gemini с поиском заявок, зон и просмотром маршрутов;
  доступен также прежний текстовый режим Anthropic. Без ключа работают заявки,
  маршруты и аналитика по правилам.
- **Кабинеты трёх ролей** — бизнес (SME), переработчик, администратор
- **Админ-панель** — статистика, графики за 14 дней, распределение по типам,
  модерация пользователей, AI-инсайты
- **Мультиязычность** — русский, английский, казахский (мгновенное переключение,
  выбор сохраняется)
- **Telegram-уведомления** — привязка аккаунта по одноразовому коду, статусы вывоза
- **Чат** между бизнесом и переработчиком (WebSocket)
- **Маркетплейс вторсырья** — объявления, заказы, статусная машина
- **ESG-отчётность** — кг переработанного сырья, CO₂, эквивалент деревьев
- **Отзывы и рейтинги** переработчиков

## Стек

| Компонент | Технологии |
|---|---|
| Бэкенд | Python 3.11, FastAPI, SQLAlchemy 2 (async) |
| БД | PostgreSQL 15 + PostGIS |
| Кэш / rate-limit | Redis |
| AI-кластеризация | scikit-learn (DBSCAN) |
| Auth | JWT (короткоживущие access-токены) + bcrypt |
| Фронтенд | Ванильный HTML/CSS/JS + Leaflet (без сборщиков) |
| Инфраструктура | Docker Compose |

## Безопасность

- Секреты только в `.env` (см. `.env.example`), в репозитории секретов нет
- Rate limiting (Redis + fallback в память): регистрация — 10 / час;
  ограничение частоты входа отключено в текущей локальной версии
- Единые сообщения об ошибках входа (нет утечки, существует ли email)
- Парольная политика (≥8 символов, буквы + цифры), bcrypt
- Роль `admin` недоступна при самостоятельной регистрации; админ создаётся
  через `ADMIN_EMAIL`/`ADMIN_PASSWORD` при старте
- Security headers: CSP, X-Frame-Options, nosniff, Referrer-Policy, HSTS (prod)
- Лимит размера тела запроса (1 МБ), лимиты пагинации, валидация всех входных данных
- Экранирование любых пользовательских данных на фронтенде (защита от XSS)
- WebSocket-чат: проверка токена и получателя, лимит длины и частоты сообщений
- Блокировки строк БД (`SELECT … FOR UPDATE`) против гонок в зонах и заказах
- Docker: non-root пользователь, Redis не публикуется наружу, БД — только на 127.0.0.1
- В production API-документация (`/docs`) отключена, стектрейсы не раскрываются

> ⚠️ **Важно:** в старой версии репозитория токен Telegram-бота был закоммичен в открытом
> виде. Этот токен скомпрометирован — **отзовите его у @BotFather** (`/revoke`) и получите
> новый. Новый токен храните только в `.env`.

## Запуск

### 1. Подготовка

```bash
git clone https://github.com/oxymerald/qosyu.com.git
cd qosyu.com
cp .env.example .env
# Заполните .env: POSTGRES_PASSWORD, SECRET_KEY (обязательно), остальное по желанию
python -c "import secrets; print(secrets.token_urlsafe(64))"   # для SECRET_KEY
```

### 2. Старт

```bash
docker compose up -d --build
```

Сайт: http://localhost:8080 · API-документация (dev): http://localhost:8080/docs

### 3. Остановка

```bash
docker compose down
```

## Структура

```
qosyu.com/
├── app/
│   ├── routers/          # auth, requests, recycler, clustering, analytics,
│   │                     # chat, marketplace, reviews, push, telegram_bot
│   ├── services/         # geo (DBSCAN + OSRM), esg, chat_manager
│   ├── static/           # фронтенд: index.html, css/, js/
│   ├── models.py         # SQLAlchemy-модели
│   ├── schemas.py        # Pydantic-схемы (валидация)
│   ├── security.py       # rate limiter, security headers, лимит тела
│   ├── auth.py           # JWT, bcrypt, парольная политика
│   ├── dependencies.py   # get_current_user, require_roles
│   └── main.py           # точка входа FastAPI
├── docker-compose.yml
├── Dockerfile
├── .env.example
└── requirements.txt
```
