# QOSYU

Платформа для сбора и вывоза вторсырья от небольших предприятий.

У кафе, магазинов и офисов часто накапливаются небольшие объёмы картона и пластика. Заказывать отдельный вывоз не всегда удобно, а переработчику может быть невыгодно ехать за каждой заявкой. В QOSYU эти заявки можно объединить в зоны сбора и построить маршрут по нескольким точкам.

Сейчас это рабочий прототип: можно пройти путь от создания заявки до завершения вывоза. Но это ещё не готовая система управления автопарком — ограничения ниже.

## Как устроен процесс

1. **Бизнес** оставляет заявку: тип материала, примерный вес и точка вывоза на карте.
2. **QOSYU** группирует соседние заявки в зоны. Для географической группировки используется DBSCAN.
3. **Переработчик** видит открытые зоны, выбирает подходящую и получает маршрут.
4. После вывоза заявка меняет статус, а объёмы попадают в статистику.

Есть ещё администратор: он видит общую статистику и управляет пользователями.

## Что уже работает

- Заявки на вывоз, статусы, история и кабинеты трёх ролей.
- Карта, поиск адреса и построение маршрутов через 2ГИС. Если сервис недоступен — резервный расчёт через OSRM или схематичная линия.
- Объединение близких заявок в зоны сбора.
- Чат бизнеса и переработчика через WebSocket.
- Telegram-уведомления о статусах вывоза.
- Маркетплейс вторсырья, отзывы и рейтинги.
- Статистика по собранному сырью и оценочные ESG-показатели.
- AI-помощник для поиска своих заявок, зон и маршрутов. Сейчас основной провайдер — Gemini; интеграция с Anthropic также предусмотрена.
- Интерфейс на русском, казахском и английском.
- Гостевая форма для заявки на пилот и отдельный демонстрационный режим без регистрации.

Демо на лендинге работает с вымышленными данными внутри вкладки браузера. После перезагрузки они сбрасываются; настоящие пользователи и рабочая БД в демо не задействованы.

## Стек

| Часть | Используется |
| --- | --- |
| API | Python 3.11, FastAPI |
| Данные | PostgreSQL 15, PostGIS, SQLAlchemy 2 |
| Кэш и лимиты | Redis |
| Группировка | scikit-learn, DBSCAN |
| Карта | Leaflet, 2ГИС, OpenStreetMap |
| Маршруты | 2ГИС Routing / Distance Matrix, OSRM |
| Фронтенд | HTML, CSS, JavaScript |
| Авторизация | JWT, bcrypt |
| Запуск | Docker Compose |

Фронтенд без отдельного сборщика: FastAPI отдаёт и интерфейс, и API. Для текущего масштаба проекта этого достаточно.

## Запуск локально

Нужны Git и Docker Desktop (или Docker Engine с Compose).

```bash
git clone https://github.com/oxymerald/qosyu.com.git
cd qosyu.com
cp .env.example .env
```

В `.env` обязательно задайте `POSTGRES_PASSWORD` и `SECRET_KEY`. Для последнего можно сгенерировать значение:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Затем:

```bash
docker compose up -d --build
```

Приложение: [localhost:8080](http://localhost:8080). API-документация в режиме разработки: [localhost:8080/docs](http://localhost:8080/docs).

Остановка:

```bash
docker compose down
```

На Windows вместо `cp .env.example .env` в PowerShell используйте `Copy-Item .env.example .env`.

### Карта и AI

Без платных API-ключей можно проверять заявки, кабинеты и базовые маршруты через резервные сервисы. Для функций 2ГИС и Gemini нужны собственные ключи. На Windows их можно добавить через `configure-apis.cmd`; скрипт записывает значения в локальный `.env`.

`/maps/status` и `/ai/status` показывают наличие настроек, но не подтверждают, что у ключа есть действующая квота. Для проверки нужен реальный запрос.

## Проверки

Быстрые тесты без рабочей PostgreSQL:

```bash
python -m pip install -r requirements-test.txt
cd app
python -m unittest discover -s ../tests -p "test_*.py"
cd ..
node --test tests/test_demo.cjs
```

Изолированные интеграционные тесты с PostgreSQL/PostGIS:

```bash
docker compose -p qosyu-tests -f compose.test.yml up -d --build --wait
docker compose -p qosyu-tests -f compose.test.yml exec -T backend python -m unittest discover -s /tests -v
docker compose -p qosyu-tests -f compose.test.yml down
```

Для сценариев, изменяющих данные, используется отдельная тестовая БД. Подробности — в [заметках по запуску](docs/OPERATIONS.md).

## Что пока не решено

- Маршрут не учитывает вместимость машины, совместимость материалов и часы приёма.
- Оптимальный порядок остановок не гарантируется. Для 2–8 точек используется матрица времени 2ГИС; при сбоях и на больших маршрутах — резервные алгоритмы.
- Если дорожные API не ответили, пунктир на карте показывает **схему**, а не навигацию по дорогам.
- Время погрузки пока условное — 6 минут на остановку. Показатели CO₂ тоже расчётные, а не подтверждённая экономия выбросов.
- Векторная карта MapGL запланирована отдельно. Сейчас используются Leaflet и растровые тайлы.

Это именно те вещи, которые нужно проверять в реальном пилоте, прежде чем полагаться на маршруты в работе.
