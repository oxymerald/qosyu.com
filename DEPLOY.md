# QOSYU: Render + Supabase

Сайт, API, карта и WebSocket-чат обслуживаются одним Docker-сервисом Render.
Supabase хранит PostgreSQL/PostGIS. Render Key Value используется для лимитов
запросов и временных кодов. Текущий интерфейс сохраняется: это публикация
существующего приложения, а не перенос на React.

## 1. Новый проект Supabase

1. Создайте отдельный проект `qosyu` на Free. Пароль базы сохраните в менеджере
   паролей. В текущей конфигурации база находится в Seoul, а Render — в Singapore.
2. В SQL Editor выполните `deploy/supabase-bootstrap.sql` из этого репозитория.
   Он включает PostGIS и создаёт схему `qosyu`, не удаляя существующие данные.
3. В **Connect → Session pooler** скопируйте PostgreSQL URI с портом **5432**.
   Подставьте пароль; специальные символы пароля должны быть URL-кодированы.
   Не используйте Transaction pooler (6543), project URL или anon API key вместо URI.
4. Не добавляйте схему `qosyu` в exposed schemas Data API. Для этого приложения
   Data API можно вообще отключить. Все операции идут через авторизованный QOSYU API.
   Supabase Auth здесь не используется; вход остаётся через `/auth`.

Приложение создаёт свои таблицы в `qosyu` и включает для них RLS без публичных
политик. Сервер работает от владельца этих таблиц; это необходимо для запросов
через SQLAlchemy. Сервисные ключи Supabase в браузере не нужны.

## 2. Render

1. Войдите в Render и выберите **New → Blueprint**, затем репозиторий
   `oxymerald/qosyu.com`, ветку `main` и `render.yaml`.
2. Убедитесь, что оба ресурса — web service и Key Value — имеют план **Free**.
   Платный тариф не требуется для первой демонстрации.
3. Заполните запрошенные переменные только в защищённых настройках Render:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Session pooler URI Supabase с паролем |
| `ADMIN_EMAIL` | Почта первого администратора облачной версии |
| `ADMIN_PASSWORD` | Новый длинный уникальный пароль администратора |
| `GEMINI_API_KEY` | Ключ Google AI Studio |
| `DGIS_API_KEY` | Ключ 2ГИС |

`SECRET_KEY` создаётся Render автоматически. `REDIS_URL` подставляется из
Key Value. Порт приложение получает из `PORT`. Если модель Gemini отличается
от указанной в manifest, задайте рабочее значение в `GEMINI_MODEL`.

Ключи можно заменить в **Environment**, затем выполнить перезапуск/deploy.
Не добавляйте секреты в GitHub, HTML или JavaScript. Старые локальные учётные
записи не появятся в новой базе автоматически.

### Проверка сертификата Supabase

TLS проверяет сертификат и имя сервера. Публичный CA-сертификат из Supabase
уже включён в `app/certs/supabase-ca.crt`, путь задан в `render.yaml`.
Если Supabase сменит сертификат или в логах появится ошибка доверия
сертификату, скачайте CA certificate в настройках базы своего Supabase-проекта,
добавьте его в Render как **Secret File** с именем `supabase-ca.crt` и задайте
`DATABASE_SSL_CA_FILE=/etc/secrets/supabase-ca.crt`. Затем повторите deploy.
Не отключайте проверку TLS для исправления этой ошибки.

### После первого запуска

- Откройте HTTPS-адрес Render и `/ready`: ответ должен быть `{"status":"ok"}`.
- Проверьте вход, новую тестовую заявку, адресный поиск, карту, дорожный маршрут
  и ответ ИИ. Сообщения чата проверяются с двумя разными аккаунтами.
- В 2ГИС проверьте, что ограничения ключа допускают выбранный серверный хостинг.
- После создания администратора уберите `ADMIN_PASSWORD` из Environment:
  учётная запись уже хранится в базе. Изменение переменной не меняет пароль
  существующего пользователя.
- Автодеплой выключен: новая версия публикуется вручную после проверки.
- Не увеличивайте число процессов/реплик до изменения доставки WebSocket-чата.

## 3. Данные и локальная версия

`docker compose` по-прежнему использует локальную базу. Облачный адрес базы
в локальный `.env` для обычного запуска подставлять не требуется.

До переноса реальных пользователей и заявок сделайте `backup-database.ps1`.
Для первого запуска рекомендуется пустая облачная база и отдельные демонстрационные
аккаунты. Импорт существующих данных — отдельный шаг: дамп локальной `public`
нельзя без проверки восстановить поверх служебных схем Supabase. Нужны явное
сопоставление таблиц со схемой `qosyu`, проверка внешних ключей и сверка числа строк.

## Ограничения бесплатной демонстрации

Render Free засыпает после 15 минут без входящих запросов; пробуждение занимает
около минуты. Перед защитой откройте сайт заранее. Supabase Free тоже имеет
лимиты и может приостанавливать неактивные проекты. Перед показом проверьте
оба сервиса. Подключённые API имеют собственные квоты.

Free Key Value не предназначен для долговечного хранения: после перезапуска
счётчики лимитов и временные коды могут сброситься. Лимит матрицы 2ГИС в приложении
не заменяет ограничения расходов в кабинете провайдера. Основные данные
пользователей и заявок хранятся в Supabase, не в Key Value.

## Проверки перед публикацией

Изолированная база тестов не затрагивает рабочую локальную базу:

```powershell
docker compose -p qosyu-cloud-test -f compose.test.yml up -d --build --wait
docker compose -p qosyu-cloud-test -f compose.test.yml exec -T backend python -m unittest discover -s /tests -v
docker compose -p qosyu-cloud-test -f compose.test.yml stop
```
